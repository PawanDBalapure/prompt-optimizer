# Example custom SDLC skill for the Prompt Optimizer.
#
# Drop files like this under:
#   <workspace>/.promptoptimizer/skills/*.md     (project-scoped)
# or set $PROMPT_OPTIMIZER_SKILLS_DIR to a folder of your own
# (user-scoped — applies to every workspace).
#
# Files ending in `.example.md`, `.template.md`, or `.sample.md` are IGNORED
# by the loader — rename this file to `a11y.md` to activate it.
#
# Reloads automatically on the next prompt (mtime-watched).
#
# -- Required fields --------------------------------------------------------
#   id    (lowercase, [a-z0-9_-], defaults to the filename stem)
#   label (human-readable name shown in listings)
#
# -- Optional fields --------------------------------------------------------
#   readOnly       true|false. Marks the mode as read-only (no file edits).
#   slashAliases   [a, b]. Slash triggers in addition to the id.
#   intentPatterns regex strings, evaluated case-insensitive.
#   keywords       plain words, auto-compiled to \b<word>\b regexes.
#   requires       [tok, ...]. AND-gate: skill ONLY fires if every token is
#                  present in the prompt (case-insensitive).
#   filePatterns   [*.css, src/ui/**]. Boosts the skill when the active file
#                  matches any glob; weaker boost for open files.
#   priority       integer -10..+10. Tie-breaker in the score-based picker.
#   tags           [foo, bar]. Free-form, surfaced in listings only.
#   rolePreface: | Block-scalar override for the role preface (otherwise the
#                  prose between the frontmatter and `## Checklist` is used).
#
# Scoring (when no slash command is given): each candidate scores
#   intent-hits × 3 + keyword-hits × 2 + active-file-pattern × 4
#   + open-file-pattern × 1 + priority
# Skills with unmet `requires` are dropped before scoring. The highest score
# wins; ties go to higher priority, then workspace > global > builtin.
#
# If `id` matches a built-in (plan, arch, code, test, review, security, qa,
# devops, docs, pr, full, bug-fix, refactor) this file OVERRIDES it for the
# current workspace. Otherwise it registers a brand-new mode.
id: a11y
label: Accessibility Auditor
readOnly: true
priority: 2
tags: [frontend, accessibility]
slashAliases: [a11y, accessibility]
keywords: [accessibility, a11y, wcag, aria, screen-reader]
filePatterns:
  - "*.html"
  - "*.tsx"
  - "*.jsx"
  - "*.vue"
intentPatterns:
  - "\bwcag\b"
  - "\bcolou?r contrast\b"

You are an Accessibility Auditor. Inspect the change for WCAG 2.1 AA
compliance: semantic HTML, ARIA roles, keyboard navigation, focus order,
colour contrast, and screen-reader announcements.

## Checklist
- All interactive elements have an accessible name (label, aria-label, etc.).
- Colour contrast meets WCAG 2.1 AA (4.5:1 for body, 3:1 for large text).
- Focus order is logical and visible focus styles are preserved.
- No information conveyed by colour alone.
- Dynamic updates use ARIA live regions where appropriate.
