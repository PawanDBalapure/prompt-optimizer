How your prompt gets optimized for Copilot

Eight smart steps run locally between your keystroke and Copilot — each one trims noise, packs only what's needed, and forecasts cost so the prompt Copilot finally sees is shorter, sharper, and cheaper:

  1. Compress filler words, softeners, and redundant phrasing.
  2. Check the local semantic cache — reuse a prior result if a similar prompt was already answered.
  3. Pack workspace context — active file, open editors, diagnostics, recent saves.
  4. Estimate token cost before the request is sent.
  5. Call Copilot & stream the answer in the sidebar (Agent) or hand you the optimized prompt to review (Optimize).
  6. Detect SDLC workflow intent from slash commands, rules, custom skills, and file context.
  7. Remember the conversation across turns per workspace — pronouns like "fix it" resolve correctly.
  8. Let you enable/edit bundled SDLC agents from the Agents button in the sidebar.

Custom skills

Workspace skills live in .promptoptimizer/skills/*.md. User-global skills via PROMPT_OPTIMIZER_SKILLS_DIR.

Supported frontmatter

  • id, label, readOnly
  • slashAliases, intentPatterns, keywords
  • requires, filePatterns, priority, tags
  • rolePreface as scalar or block (|)
  • checklist as frontmatter items or markdown bullets under ## Checklist

Skill files hot-reload on the next prompt. Diagnostics: Prompt Optimizer: Diagnose Skill Loading Errors.

🤖 Agents button

The Agents chip in the sidebar opens a multi-select picker for the bundled SDLC agent library.

  • Tick an agent to enable it for the current workspace.
  • Untick to disable it.
  • Click the ✎ pencil to enable-and-open the workspace copy for editing.
  • Click ↺ reset to restore the bundled definition over local edits.
  • Use the title-bar + to create a custom agent from a template.

Enabled agents are copied into .promptoptimizer/skills/ — customize them like any other skill.

The memory lifecycle — three distinct stages

Every saved file, every committed prompt, and every memory file passes through three stages — all local. Storage lives in .promptoptimizer/ next to your workspace and in VS Code's globalState.

① Ingestion

Files saved → workspace memory (AGENTS.md, CLAUDE.md, .promptoptimizer/memory.md) re-read; Copilot chat history, git log, README and active editors are harvested.

② Storage

Tokens, embeddings, and conversation turns are committed to a local SQLite cache + JSON state. Prompt versions live in a Git-style graph with branches, tags, and parent links.

Embedding bricks falling into the SQLite vault.

③ Retrieval

Prompt arrives → semantic cache lookup → matching context repacked → only the optimized prompt + token forecast pass to Copilot. Raw file text and secrets never leave your machine.

🔒 Privacy & security

Data processing100% on your machine — no cloud backend, no remote API except the Copilot request you approve.
Prompt storageCached locally in a SQLite file (promptProxy.dbPath). Never uploaded.
Secret scanningAPI keys and tokens are detected before any network call and blocked with a warning.
TelemetryNone. Zero usage or diagnostic data collected.
Network callsOnly the GitHub Copilot inference request you explicitly send via the VS Code Chat API.
Open sourcegithub.com/PawanDBalapure/prompt-optimizer — audit it yourself.

To verify: open out/extension.js or engine/dist/. Search for http, fetch, axios, request — you'll find zero outbound calls outside the Copilot API.

🚨 Secret detection patterns

If your prompt contains anything that looks like one of these, a warning appears in the panel before the prompt is sent:

  • OpenAI keys — sk-…
  • Anthropic keys — sk-ant-…
  • GitHub tokens — ghp_…, ghs_…
  • AWS access keys — AKIA…
  • PEM private key headers
  • Generic assignments — password=, token=, api_key=

Manage patterns via the panel ⚙ Secret detection menu — add or remove regex / startsWith / contains rules per workspace.
